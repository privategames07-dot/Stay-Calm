색상·수치의 기준 파일은 style.css이다. Android에서 웹뷰를 유지하면 UI를 다시 구현할 필요가 없다. 상태 표시줄·시스템 내비게이션을 고려하고, OS 뒤로가기는 열린 대화상자 또는 메뉴부터 닫도록 연결한다.

## 기록 및 콤보

- 기기 현지 시각을 사용한다. 시작 시각은 포함하고 종료 시각은 제외한다. 공강은 ‘수업 외’에 저장한다. 겹치는 수업은 탭 시 사용자가 선택하며 첫 탭의 시각으로 저장한다.
- 1탭은 1회다. 같은 날짜·수업에서 이전 입력과 5초 미만이면 콤보가 이어지고 3회째부터 숫자와 붉은 광채를 표시한다. 마지막 입력 5초 후 표시가 사라진다. 최대 배경 불투명도는 0.22다.
- 효과를 끄면 콤보 숫자와 파동·배경 효과를 숨긴다. 시스템 동작 줄이기는 파동·버튼 축소·붉은 빛을 줄인다. 화면이나 수업 전환, 앱 백그라운드 이동 시 콤보를 초기화한다.
- 실제 탭 시각에 현재 수업을 다시 계산한다. 순위는 수업 안에서 발생한 입력만 사용하며 수업 외 건수는 별도 표시한다. 동점은 공동 순위다. 누른 횟수는 사용자의 주관적인 지표다.

## 데이터 형식

웹 저장소 키는 staycalm.v1. 접두사로 시작한다. 하나의 날짜 기록을 JSON 배열로 저장해 빠른 입력 시 순서대로 반영한다. 저장 실패 시 알림을 표시한다.

| 키 (접두사 생략) | 내용 |
| --- | --- |
| slots | 수업 배열. id는 UUID, name은 과목명, weekday는 일=0~토=6, start/end는 자정 이후 분 |
| day.YYYY-MM-DD | 입력 배열. id, at(유닉스 밀리초), day(현지 날짜), hour(0~23), clock(HH:mm), slot |
| 각 입력의 slot | 해당 시점의 id/name/start/end 사본 또는 수업 외이면 null |
| settings | haptics와 effects 불리언. 각 기본값 true |

같은 이름을 가진 과목의 주간 횟수는 합산한다. 날짜별 상세 내역은 당시 수업 ID와 이름·시간으로 구분하므로 시간표 수정 전 기록도 유지된다. 백업·복원, 학기별 시간표, 날짜 한정 휴강/보강, 시간당 보정 점수는 1.1에 포함하지 않았다.

## 플랫폼 연결

- iOS가 선택한 사진 한 장을 방향 보정하고 긴 변 최대 2200px로 축소한다. Vision의 정확도 우선 모드와 ko-KR/en-US로 인식한다. 화면에 이미지와 OCR 결과만 전달한다. 앱은 원본 캡처를 파일로 보관하지 않는다.
- JS 공통 입구는 receiveTimetable(dataURL, words)이다. 각 단어는 {text, x, y} 구조이고 x/y는 왼쪽 위 기준 0~1의 중심 좌표다. Android는 시스템 사진 선택기와 한국어를 지원하는 기기 내 OCR을 이 입구에 연결하면 된다. 진동은 기존 iOS 브리지 호출 위치에 Android의 가벼운 탭 피드백을 연결한다.
- 요일 경계인 세로선과 일정 간격의 가로 눈금을 함께 찾고, 왼쪽 시간 열의 숫자 여러 개로 첫 시각을 추정한다. 자동 인식 화면에서 첫 시각을 확인·수정할 수 있다. 표를 찾지 못하거나 사용자가 범위를 다시 지정하면 원래의 두 점 지정 방식을 사용한다.
- 각 요일의 30분 구간에서 여러 지점의 색을 조사해 다수인 채색을 사용한다. 붙은 구간의 색이 바뀌면 수업을 나눈다. 인식·직접 등록·수정은 00분과 30분을 기본 선택지로 사용한다. 이전 데이터의 분 단위 시각은 해당 항목에만 선택지로 보존한다.
- iOS는 courseNames 브리지로 각 수업 칸의 정규화 사각형을 받아 그 부분만 다시 OCR한 뒤 receiveCourseNames(token, groups)에 전달한다. 그룹의 각 줄에는 text, x, y, h가 들어가며 좌표와 글자 높이는 잘라낸 칸 기준이다. 과목 줄을 합치고 강의실 패턴이나 글자 크기 차이에서 중단한다. 사용자가 저장하기 전 이름·요일·시간을 검토한다.
- 같은 색으로 연달아 배치된 수업, 무채색 테마, 작은 이름, 여러 줄 과목명에서는 수동 수정이 필요할 수 있다. 사용자가 확인 후 저장해야 반영된다. 에브리타임 계정 로그인, 공유 링크 동기화, 외부 OCR 전송은 구현하지 않았다.
- 외부 웹사이트를 로드하지 않는 앱 내부 웹뷰에서만 네이티브 브리지를 제공한다. Android 릴리스 테스트는 ① 기기 재시작 후 기록 복구 ② 연타 ③ 수업 종료 정각 ④ 일·월 경계 ⑤ 겹치는 수업 ⑥ 캡처 한 장의 선택·취소·수정 저장 ⑦ 폰트 확대·뒤로가기 순으로 진행한다.

## 빌드 3 · 입력과 콤보 연출

실제 버튼은 원의 지름에 좌우·상하 각각 18~32 CSS px의 여백을 더한 사각형이다. 아이콘의 표시 크기는 종전과 같다. 탭 시 3콤보부터 시계 방향으로 이동하는 원주 접촉점에서 접선 속도 (−sin θ, cos θ)와 작은 바깥쪽 속도를 합쳐 불티를 방출한다. 콤보에 따라 접촉점·입자 수가 늘어나고 최대 220개로 제한한다.

100회, 그리고 500회부터 매 500회째에 글자만 680ms 동안 세로축으로 두 바퀴 회전하며 위로 떠오른다. 650ms에 금색·주황·분홍 불꽃과 정확한 달성 횟수가 나타난다. 축하 중에도 버튼은 입력을 받는다. 현재 콤보 유예 시간과 1탭 1회 기록을 유지한다. 효과를 끄면 시각 연출을 생략하며 동작 줄이기에서는 달성 문구만 표시한다. web/effects.js와 web/style.css를 함께 사용한다.

## 빌드 4 · 원 둘레 전체 스파크

3콤보부터 원주 중 min(콤보/50, 1) 구간을 시계 방향으로 밝힌다. 25콤보는 반원, 50콤보 이상은 360도다. 밝은 중심선과 주황색 광채를 겹치고, 55ms 간격으로 최대 40개 접촉점에서 접선 방향으로 불티를 발사한다. 콤보 타이머가 끝나면 원주와 발사를 멈추고 남은 입자만 소멸한다. 효과 끄기 및 동작 줄이기 설정을 따른다.

## 빌드 5 · 길게 누르기

참기 버튼 영역과 그 안의 콤보 문구는 텍스트 선택을 끈다. iOS에서는 길게 누를 때의 기본 메뉴도 이 영역에서 끈다.

## 빌드 6 · 컴시간 학생용 캡처

`web/school.js`는 좌상단 원점의 정규화 좌표를 사용한다. 주간표 가로선과 7개 세로선을 찾아 교시 열과 월~금 5열을 나눈다. 아래 학년 전체 표는 제외한다. 셀 상단의 어두운 글자로 수업 유무를 판정하고 해당 부분만 한국어 OCR에 보내 과목명을 읽는다. 교사명과 빈 강조 칸은 저장하지 않는다.

학교명에서 학교급을 찾아 사용자가 확인한다. 각 교시 왼쪽 시각을 우선 사용하고 실패하면 해당 칸만 다시 읽는다. 인식되지 않은 시각에는 추정 표시를 하고 수정할 수 있게 한다. 기본 수업 길이는 중학교 45분, 고등학교 50분이고 추정할 때만 쉬는 시간 10분을 더한다. 각 교시의 종료는 시작 + 수업 길이로 계산하고 분 단위를 유지한다. 저장 시 기존 주간 반복 모델과 중복 처리 규칙을 사용한다.

## 빌드 8 · 입력을 멈췄을 때 콤보 유지시간 표시

콤보 효과가 켜진 상태에서 3회째부터 횟수 아래 4px 간격으로 76×3px 빨간 바를 표시한다. 왼쪽 끝을 고정하고 5초 동안 오른쪽 끝을 일정한 속도로 줄인다. 누르는 동안과 탭을 마친 직후에는 바를 숨긴다. 마지막 탭 뒤 250ms 동안 입력이 없으면 남은 4.75초에 해당하는 길이부터 표시한다. 매 입력마다 만료 시각을 갱신하고 콤보 초기화 시 숫자와 바를 함께 숨긴다. 바는 터치 입력을 받지 않는다.

## 빌드 9 · 시간표 전체 초기화

등록 수업이 있으면 시간표 화면에 시간표 초기화 버튼을 표시한다. 확인 창에 삭제할 수업 수와 모든 요일을 초기화한다는 범위를 표시하고 취소와 전체 초기화를 제공한다. slots 저장이 성공하면 선택 수업과 콤보 상태를 비우고 화면을 갱신한다. day 날짜별 기록에 보관한 수업 스냅샷과 통계는 보존한다. 저장 실패 시 확인 창과 기존 시간표를 유지한다.

## 빌드 10 · 상점과 과목별 이펙트

마지막 탭을 기준으로 1초간 바를 숨긴 뒤 가득 찬 상태에서 4초 동안 줄인다. 만료 시각은 마지막 탭 + 5초다.

하단 상점 탭에서 적용할 수업을 선택한다. 기본 브레이크 불티는 무료이며 서리 결정 500, 번개 2,500, 유성우 5,000, 오로라 10,000크레딧이다. 이펙트는 계정 없이 기기에서 한 번 해금하고 과목별로 하나씩 장착한다. 렌더링은 web/effects.js를 공유한다. 효과 끄기와 동작 줄이기 설정을 따른다.

잔액은 모든 날짜의 저장된 탭 수(기존 기록과 수업 외 포함)에서 실제 결제액을 뺀 값이다. staycalm.v1.shop에 효과별 결제액 paid와 과목별 장착값 equipped를 저장한다. 이름은 공백을 양끝에서 제거하고 NFC로 정규화한 뒤 course:를 붙인다. 수업 외 키는 outside이다. 시간표 초기화 뒤 같은 과목을 등록하면 장착값을 다시 사용한다. 잔액 부족 시 취소와 빨간 치트로 구매 버튼을 표시하고 치트 구매는 결제액 0으로 기록한다.

## 빌드 11 · 성장과 배포

손끝 단련은 수동 입력당 1+레벨, 집중 타격은 수동 10콤보마다 레벨×5점을 추가한다. 햄스터는 앱이 보이는 동안 5초마다 레벨만큼 자동 기록한다. 수업이 겹치고 선택되지 않았으면 해당 주기를 건너뛴다. 펫은 수동 콤보에 영향을 주지 않는다. 성장 비용은 기본가(20, 40, 60)×다음 레벨의 제곱이다. 영구 레벨과 실제 지출액은 shop에 함께 저장한다. 이벤트 count 누락은 1점으로 처리하고 source로 수동·펫을 구분한다. 점수를 수업 기록·주간 통계·크레딧에 반영한다.

향후 1:1은 경기마다 빈 레벨 맵과 독립 지갑으로 시작해 Growth.score와 Growth.cost를 재사용한다. 5분 종료 시 높은 점수가 이긴다. 경기 시계, 점수와 구매 검증은 서버에서 처리하고 테스트 치트는 싱글 전용으로 둔다. 이번 빌드는 싱글 플레이만 제공한다.

iOS 배포는 빌드별 GitHub Release에 IPA·source.json·아이콘을 첨부한다. 설정에서 최신 릴리스를 연다. 비공개 저장소에서 Releases는 접근 권한이 필요하다.

## 빌드 12 · 피버타임

100 및 500의 양의 배수인 수동 콤보 달성 탭부터 5초간 수동·펫 점수에 배수를 적용한다. 재달성하면 지속시간을 갱신한다. 100콤보 계수는 1+강화 레벨/10(최대 2.0), 그 이후는 (100콤보 계수+1)×달성 콤보/100이다. 점수와 크레딧은 0.1 단위로 합산한다. 기존 집중 타격 레벨은 최대 10까지 피버 레벨로 계승한다. 축하 글자는 미리 분리한 투명 PNG를 980ms 동안 세로축으로 한 바퀴 회전하며 위로 이동하고 49% 크기로 줄인다.

## 빌드 13 · 전체 이펙트

적용할 수업 목록은 전체, 수업 외, 과목명 순서다. 전체 적용 시 equipped를 {all: 효과 ID}로 저장하고 개별 설정을 비운다. 개별 과목과 수업 외 설정은 전체값보다 우선한다. 새 과목도 전체값을 상속한다. 과목별 설정이 섞인 상태에서는 전체 화면에 적용 중인 항목을 표시하지 않는다.

## 빌드 14 · 피버 계수 강화

모든 피버는 달성 탭부터 10초간 지속된다. 100콤보는 레벨에 관계없이 2배다. 500부터 매 500콤보에서 (7 + log₂(min(콤보, 10000) / 500)) × (1 + 레벨 / 10)을 적용한다. 최고 레벨은 10이다. 기존 fever 레벨을 재사용하고 이전 focus 레벨도 같은 방식으로 계승한다. 배수는 화면에서 소수 둘째 자리까지 표시하고, 수동 입력과 펫 정산 시 점수는 소수 첫째 자리로 반올림한다.

## 빌드 15 · 피버 화면과 제스처

참기 화면에서 피버가 활성화되면 버튼과 터치 영역을 1.13배 확대하고 네 가장자리에서 바깥으로 달려 나가는 붉은 속도선 36개를 표시한다. 피버 종료 시 원래 크기로 복귀한다. 콤보 효과 끄기를 따르며 동작 줄이기에서는 버튼 크기만 바꾼다. 일반 화면 문구는 선택할 수 없고 입력칸은 편집할 수 있다. 페이지 확대를 끄고 한 손가락 스크롤을 유지한다.

## 빌드 16 · 참기 화면 고정

참기 화면에서 overflow:hidden과 touch-action:none을 적용해 위아래 스와이프를 막는다. 루트 페이지의 overflow와 overscroll을 차단하고 iOS 루트 스크롤뷰의 bounces를 끈다. 다른 탭의 main과 dialog는 기존 스크롤 영역을 사용한다.

## 빌드 17 · 다중클릭 상한과 비용

다중클릭은 기본 Lv.1에서 1점, Lv.5에서 5점이다. 내부 tap 값은 구매 횟수 0~4를 유지한다. 모든 로드와 점수 계산에서 기존 높은 레벨을 4로 제한하고 과거 지출과 기록은 유지한다. Lv.2~5 강화 비용은 각각 500, 2000, 5000, 10000크레딧이다. 최대 레벨은 구매를 차단한다. 피버 배수는 최대 기본 점수 5점에 곱해진다.

## 빌드 18 · 펫 레벨

기본 Lv.0은 자동 클릭 0회이며 레벨과 5초당 기본 점수가 일치한다. 최대 레벨 20을 로드와 점수 계산에서 제한한다. 기존 상한 초과 펫은 20으로 적용한다. 다음 레벨 제곱 ×50크레딧을 사용해 Lv.1 50, Lv.10 5000, Lv.20 20000이 든다. 피버 배수는 이 기본 점수에 곱한다.

## 빌드 19 · 펫 클릭 배수

petPower는 내부 0~4를 화면 Lv.1~5로 표시한다. 기본 1배, 최대 5배이고 다중클릭과 500/2000/5000/10000 비용을 공유한다. 자동 점수는 pet(0~20) × (1+petPower) × 피버 배수다. 직접 클릭 점수는 tap만 참조한다. 기존 데이터의 petPower 누락은 0으로 처리한다.

## Android 네이티브 구현

android/app은 Java WebView와 ML Kit 한국어 인식 모델을 포함합니다. WebViewAssetLoader로 로컬 번들을 HTTPS 원점에서 열어 기록을 유지합니다. android-bridge.js가 기존 메시지 인터페이스를 연결합니다. 사진은 EXIF 방향을 보정하고 최대 2200px로 축소하며 전체 및 셀별 OCR을 동일 좌상단 좌표로 반환합니다. 인터넷 접근 없이 모델을 사용합니다. 앱 비활성화 시 펫 타이머를 멈춥니다. 테스트 키로 서명한 APK와 에뮬레이터 검증을 GitHub Actions에서 생성합니다.

## 빌드 20 · 크리티컬·거북이·새 이펙트·태블릿

Growth.locked로 상점 UI와 구매 처리 모두 선행조건을 검사한다. 크리티컬 확률 critical 0~10은 레벨/100 확률로 입력 묶음에 한 번 판정한다. 피해 강화 criticalHit는 확률 Lv.5 필요, 내부 0~19를 화면 Lv.1~20로 표시하고 5+5×레벨/19 배수다. 잠겨 있을 때 기본 5배다. 확률 강화 비용은 500×다음 레벨², 피해는 1000×다음 내부 레벨²다.

feverEase는 fever Lv.10 필요, 0~10레벨이며 첫 피버 max(20,100−20×레벨), 나머지는 500의 배수 단계에서 20×레벨을 뺀다. 배수 계산은 원래 단계를 사용한다. 비용은 1000×다음 레벨²다.

기존 pet을 토끼로 명명하고 저장 ID는 유지한다. pet20과 petPower4 필요, turtle 해금은 30000, 토끼와 함께 활동한다. 15초 기본 주기를 1+0.1×turtleSpeed(0~10)로 나눈다. 기본 피해는 200×(1+turtleDamage), 내부 피해 0~9가 표시 Lv.1~10이다. 속도 비용은 1000×다음 레벨², 피해는 1500×다음 내부 레벨². 단일 250ms 스케줄러로 두 펫을 실행하고 미접속 중 점수는 쌓지 않는다. 자동 기록은 같은 분·수업·종류·크리티컬 여부일 때만 병합한다.

ink는 터치마다 반투명 먹물 반점이 확산하고 소멸한다. nova는 붉은 균열 테두리와 피버 진입 충격파를 쓴다. 최대 입자 수를 제한하고 동작 줄이기와 효과 끄기를 따른다. iPad는 UIDeviceFamily 1,2와 4방향 회전을 지원하고 600px 이상에서 3행 중앙 정렬한다.

## 빌드 21 · 최고 콤보와 분별 기록

수동 이벤트 combo를 새로 저장한다. 기존 이벤트는 날짜·수업 ID와 5초 미만 간격으로 콤보를 복원한다. 자동 기록은 콤보를 올리지 않는다. 역대 최고는 정규화한 과목명별로 모든 날짜에서 구한다. 홈·시간표·기록에 표시한다. 기록 UI는 수업별 분 단위 수동/자동 점수를 합산한다. day.* 원본 JSON을 수정하거나 삭제하지 않고 설정 원본 로그에서 같은 저장 자료를 읽는다. 두 펫은 요약에서 합산하고 원본 source에서 구별한다.

## 빌드 22 · 거북이 기본 주기 변경

거북이 기본 주기를 30초로 변경한다. 속도 Lv.0은 30초, 속도 Lv.10은 15초다. 피해·가격·해금 조건은 빌드 20 명세를 따른다.

## 빌드 23 · 스킬 표시 전수 점검과 페인트 튐

상점의 효과 설명이 항상 다음 레벨을 표시해 마지막 두 레벨에서 수치가 같아 보이던 문제를 수정한다. Growth.displayLevel로 표시 레벨을 정하고 현재와 다음 효과를 함께 표시한다. 최대 레벨은 현재 효과만 표시한다. Growth.normalizeLevels로 모든 저장 스킬 레벨을 정수·유효 범위로 제한한다. 크리티컬 피해는 기존 표시 Lv.1~20와 저장 0~19를 유지하며 19는 9.7368, 20은 정확히 10배다. 거북이 속도는 표시·저장 모두 0~10이며 9는 1.9, 10은 2배다.

수묵화는 20개 꼭짓점으로 된 불규칙한 자국과 8개 작은 방울을 각 자국마다 그리고 소멸시킨다. 클릭당 자국 수는 콤보에 따라 8~60개이며 50콤보부터 전 둘레에 균등 분산한다. 자국은 최대 300개로 제한한다.

## 빌드 24 · 크리티컬 후광과 피버 종료

크리티컬 시 레이아웃 텍스트를 추가하지 않는다. 금색 글자 마스크와 절대 배치한 후광을 450ms 동안 한 번 표시한다. 효과 끄기를 따르고 동작 줄이기에서는 글자 색만 표시한다. resetCombo는 피버 만료 시각과 배수를 초기화하고 확대와 속도선을 함께 제거한다.

빌드 24의 주 탭 이름과 Android 네이티브 복귀 경로는 인내로 통일한다.

## 빌드 25 · 유지관리

스킬 초기화는 levels와 skillSpent를 비워 실제 강화 지출만 환급한다. 펫 타이머와 피버를 재설정하고 이펙트 구매는 유지한다. 로그 삭제는 logState에 새 epoch와 기존 누적 획득 코인 creditCarry를 한 번에 기록한 뒤 이전 day.*와 logs.* 키를 정리한다. 이후 기록은 logs.<epoch>.day.<날짜>에 저장한다. 포인터 교체가 먼저 이뤄져 정리 중 중단되어도 잔액과 새 기록이 일관된다. 최고 콤보는 현재 epoch 이벤트만 읽는다. 캐시 삭제는 WebView 메모리·디스크 캐시와 임시 인식 이미지만 삭제한다.


## 0.26 · 빌드 26 · 버전 통일과 실행 시 알림

scripts/sync-version.py는 CFBundleVersion에서 CFBundleShortVersionString과 web/version.js를 생성한다. Android versionCode는 같은 정수이고 versionName도 생성된 plist를 따른다. 네이티브 updateCheck는 공개 source.json을 HTTPS로 요청해 buildVersion과 플랫폼별 다운로드 주소를 JS에 전달한다. 실행 때 자동 확인하고 설정에서는 수동 재확인한다. 업데이트 알림은 열린 입력창이 닫힌 후 표시한다. 버전 문자열 대신 정수 빌드로 비교한다.

이전 공개 Releases의 unsigned IPA plist와 웹 표시, APK manifest와 웹 표시를 교정한다. APK는 현재 CI 테스트 키로 다시 서명하고 aapt·apksigner로 검증한다. 서명키를 업로드하지 않는다. 이전에 설치한 APK와 서명 호환은 보장하지 않는다.
